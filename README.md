# KordRP — реестр Республики Кордония (v8)

Личные дела, удостоверения, кадровые приказы, трудовая, проверка жетонов. Node.js 22 + SQLite.

## Запуск
```
npm install
npm start        # запускает boot.js: проверка базы, восстановление, затем сервер
```
На Render: Build `npm install`, Start `npm start`, переменные — в Environment (см. `.env.example`).

## Вход главного администратора
Логин и пароль берутся из `ADMIN_USERNAME` и `ADMIN_PASSWORD` (по умолчанию в примере `GGsmokerr`).
Если в базе уже есть единственный главный администратор со старым логином `owner1` или `admin`, при старте с новым
`ADMIN_USERNAME` он **переименуется**, пароль останется прежним. Любому пользователю логин можно сменить на вкладке «Пользователи».

## Что внутри
- **Реестр**: поиск, фильтры, карточки и таблица, CSV. Дела создаются как **черновик**; кнопка «Опубликовать» делает дело видимым,
  **автоматически выдаёт удостоверение** и пишет «Приём» в трудовую.
- **Личное дело** открывается большим окном: обзор, удостоверение, аттестации, приказы, история. Печать.
- **Удостоверение** рисуется как картинка (SVG) на лету: фото, ФИО, звание с погонами, должность, жетон, № и срок. Нет фото — поле пустое,
  после загрузки фото оно появляется само. Скачивание **PNG** и SVG.
- **Фото** загружаются файлом (сжимаются в браузере) и хранятся в базе, поэтому попадают в резервные копии.
- **Засекреченная личность**: галочка в деле. Для всех без права «Видеть засекреченных» вместо ФИО/фото показывается фото жетона
  (в реестре, проверке жетона, удостоверении, истории, поиске игроков). Жетон, звание, погоны и действительность видны.
- **Проверка жетона** показывает погоны, удостоверение и статус.
- **Моё дело**: своё дело (привязка по жетону из профиля) + поиск чужих дел при праве «Открывать чужие дела».
- **Игроки**: поиск по нику/ФИО/Discord/жетону, где работает, жетон, № удостоверения. Трудовая и паспорт — по правам.
- **Трудовая** (только в профиле игрока): приём, переводы, звания, должности, увольнения, взыскания, поощрения и **судимости** (с отметкой «погашена»).
  Изменения службы пишутся в неё автоматически.
- **Приказы**: приём, перевод, повышение/понижение, назначение, увольнение, взыскание, поощрение. Применяются к делу сразу, нумеруются (П-2026-0001).
- **Исключение из организации**: дело уходит в архив (данные и трудовая сохраняются), удостоверение недействительно; можно вернуть.
- **Организации и звания**: добавление, переименование, удаление (с переносом дел), цвет, порядок, звания со звёздами погон, должности, подразделения.
- **Права доступа**: матрица «роль × право», область «своя организация / все», свои роли. Применяется сразу.
- **Регистрация**: заявка → одобрение главным администратором (роль и организация назначает он).

## Права по умолчанию (меняются на вкладке «Права»)
| Роль | Область | Главное |
|---|---|---|
| Главный администратор | все | всё, не настраивается |
| Технический администратор | все | просмотр, чужие дела, история, приказы, трудовая, игроки, журнал |
| Руководитель организации | своя | дела, публикация, исключение, приказы, аттестации, трудовая, секретность |
| Кадровик | своя | как руководитель, без постановки секретности |
| Следствие / надзор | все | реестр, чужие дела, история, аттестации, поиск игроков (без трудовой и паспорта) |
| Просмотр | своя | только реестр и проверка жетона |

Пользователи, регистрации, права и резервные копии доступны только главному администратору.

## Сохранность данных
- При каждом запуске база проверяется (`integrity_check`); при повреждении она откладывается и восстанавливается из копии.
- Копии: локальные (папка `backups`, каждые 6 часов и при остановке) и **зашифрованные в GitHub** (отдельная ветка `data-backup`, чтобы не запускать деплой сайта).
  Отправка — через 3 минуты после любого изменения, но не чаще раза в 10 минут, и при остановке сервера.
- **Если диск пуст (бесплатный Render после перезапуска), данные автоматически поднимаются из GitHub-копии.**
  Если GitHub был недоступен при старте, отправка блокируется, чтобы не затереть копию пустой базой.
- Вкладка «Копии и база»: сделать/скачать копию, проверить базу, очистить лишние файлы, восстановить из файла / GitHub / локальной копии (по паролю админа).
- Настройка GitHub-копии: приватный репозиторий + fine-grained токен (Contents: Read and write) + переменные `BACKUP_GITHUB_TOKEN`, `BACKUP_GITHUB_REPO`, `BACKUP_KEY`.
- Альтернатива — платный Persistent Disk Render: `DATA_DIR=/var/data/data`.

## Безопасность
Пароли — bcrypt; сессии в базе; защита от CSRF; ограничение частоты входа, регистрации и проверки жетонов; строгая CSP; фото и удостоверения видны только вошедшим.
