# KordRP — полный прототип кадрового реестра

Это уже не один локальный HTML-файл: проект включает сервер, SQLite-базу, вход по ролям и отдельную публичную проверку жетона.

## Что есть
- проверка жетона `000-000` (доступна после входа в систему);
- приватный кадровый список;
- профили с ФИО, датой рождения, паспортом, телефоном, OOC-ником и Discord;
- организации и списки званий;
- автоматический схематический предпросмотр погон при выборе звания;
- служебные удостоверения: номер (создаётся автоматически), даты, статус, ссылка или загрузка изображения;
- кадровая история и аттестации;
- роли пользователей и ограничение редактирования по организации;
- журнал входов и проверок жетонов;
- SQLite-хранилище, загрузка изображения удостоверения (только для вошедших);
- отключение пользователей, сброс и смена пароля, защита от CSRF и подбора пароля;
- тёмный интерфейс, адаптированный под телефон.

## Важно перед использованием
Это основа для дальнейшего запуска, а не уже размещённый в интернете сервис. Перед реальными данными нужно проверить весь проект, настроить хостинг, постоянный диск, HTTPS, резервные копии, правила доступа и политику хранения персональных данных. Не вводите настоящие паспортные данные в демонстрационный или незапущенный сервер.

## Запуск на компьютере
Нужен Node.js 20+.

1. Распакуйте ZIP.
2. В папке проекта выполните `npm install`.
3. Скопируйте `.env.example` в `.env` (файл подхватывается автоматически).
4. Задайте уникальные значения `SESSION_SECRET`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`.
5. Выполните `npm start`.
6. Откройте `http://localhost:3000`.

Первый администратор создаётся автоматически при первом запуске на основе `ADMIN_USERNAME` и `ADMIN_PASSWORD`. Не оставляйте пароль `change-this-immediately`.

## Размещение в интернете
Загрузите проект в GitHub и подключите репозиторий к Node.js-хостингу, который поддерживает Node 20+, переменные окружения и постоянный диск. В настройках хостинга задайте:
- `SESSION_SECRET` — длинный случайный секрет;
- `ADMIN_USERNAME` — логин главного администратора;
- `ADMIN_PASSWORD` — сильный пароль;
- `DATA_DIR` — папка на постоянном диске;
- `UPLOAD_DIR` — папка на постоянном диске;
- `NODE_ENV=production`.

SQLite-файл и изображения должны храниться на постоянном диске, а не на временной файловой системе контейнера. Убедитесь, что хостинг поддерживает сохранение файлов между перезапусками.

## Использование с телефона
Проект можно загрузить в GitHub через мобильный браузер, затем открыть в браузерном IDE/Node-хостинге. Само редактирование больших файлов на телефоне неудобно; практичнее загрузить архив в GitHub и развернуть репозиторий на Node.js-хостинге.

## Ограничения текущей версии
- Это не интегрировано с GoreBox: внутриигровая команда проверки не реализована и не обещается без подтверждённого API/моддинга.
- Погоны пока условные, не точные официальные таблицы знаков различия. Они намеренно не содержат флагов РФ.
- Для ролей следствия/надзора нужно дополнительно настроить точную политику доступа и организационные границы под окончательный регламент проекта.
- Для production стоит добавить восстановление доступа, автоматические бэкапы и полноценные тесты. Ограничитель попыток входа хранится в памяти процесса и сбрасывается при перезапуске.


## Обновление интерфейса авторизации

- До входа доступна только вкладка «Проверка удостоверения» с предложением войти; сам запрос проверки защищён серверной авторизацией. При недействительном удостоверении показывается причина.
- После входа доступны рабочие вкладки согласно роли.
- Добавлена вкладка «Моё дело». Для автоматической привязки кадровой карточки логин пользователя должен совпадать с игровым ником сотрудника или его Discord-полем в кадровой записи. Если карточка не находится, администратору нужно проверить совпадение этих полей.
- Перед публичным запуском задайте уникальные `ADMIN_USERNAME`, `ADMIN_PASSWORD` и `SESSION_SECRET` на хостинге. Не используйте реальные персональные данные в демонстрационном окружении.


## Исправления
- Удостоверение создаётся автоматически при сохранении сотрудника; даты, номер и изображение обновляются при редактировании.
- Статус удостоверения синхронизируется со статусом сотрудника (увольнение → «Недействительно», возобновление → «Действует»).
- В production сервер не запустится со стандартными `SESSION_SECRET`/`ADMIN_PASSWORD`; включён `trust proxy`, чтобы вход работал за прокси хостинга.
- Исправлены: имя сотрудника в аттестациях, звёзды погон («Подполковник» = 2), живой предпросмотр погон, доступ к `/uploads` только после входа, проверка прав при загрузке изображения, JSON-ответы на неизвестные API-пути.

## Деплой на Render
- Node закреплён на 22.x (`engines` и `.node-version`): для `better-sqlite3` нет сборок под Node 26.
- Build command: `npm install`, Start command: `npm start`.
- Переменные: `NODE_ENV=production`, `SESSION_SECRET` (24+ символа), `ADMIN_PASSWORD` (10+ символов), `ADMIN_USERNAME`.
- Для сохранения данных между деплоями подключите Persistent Disk и задайте `DATA_DIR=/var/data/data`, `UPLOAD_DIR=/var/data/uploads`. Без диска база и загрузки обнуляются при каждом деплое.
